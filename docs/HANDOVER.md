# 인수인계 문서 — OG키보드 (og-keyboard-mac)

> 이 문서는 사람과 AI 작업자(Claude, Muse 등)가 번갈아 작업할 때의 **유일한 공유 기록**이다.
> 채팅 맥락은 서로 넘어가지 않으므로, 작업 상태는 반드시 이 문서에 남긴다.
> 상세 분석(버그 근거·최적화)은 [ANALYSIS-2026-11-12.md](ANALYSIS-2026-11-12.md) 참고.

## 작업 규칙 (모든 작업자 공통)

1. **시작 전**: 이 문서와 분석 문서를 읽고, `git pull`로 최신 상태에서 시작한다. 다른 작업자가 진행 중인 항목은 건드리지 않는다.
2. **범위**: 한 번에 한 항목(B1, O3 등)만 잡는다. 항목 번호를 커밋 메시지에 넣는다. 예: `B1: 입력 내용 로그를 길이만 남기게 정리`
3. **끝나면**: 아래 "현재 상태"의 체크박스와 "작업 로그"를 갱신해 **같은 커밋**에 포함한다. 상태 표기가 코드보다 오래되면 그게 곧 버그다.
4. **main 푸시 = 빌드 실행**: main에 푸시하면 GitHub Actions가 테스트+빌드를 돌리고 결과물을 아티팩트로 올린다 (릴리스는 안 만듦). 깨진 상태로 main에 푸시하지 않는다. 자신 없으면 브랜치 + PR로.
5. **릴리스**: 태그 `vX.Y.Z`를 올릴 때만 릴리스가 만들어진다. 태그 전에 `App/Info.plist`의 `CFBundleShortVersionString`을 태그와 맞춘다 (B8, 아직 수동).
6. **검증**: 맥이 없는 작업자는 로컬 빌드가 안 된다 — push 후 Actions 결과로 확인한다. 실기(실제 맥 입력 동작) 확인이 필요한 항목은 "실기 확인 필요"라고 명시하고 완료 처리하지 않는다.

## 프로젝트 개요

- 애플 실리콘 맥용 한글 입력기 (InputMethodKit). macOS 13+, Swift, 네트워크 기능 없음.
- 자판: 세벌식 390·391·순아래, 두벌식. 모아치기, 한자·이모지, 바로잡기, 텍스트 단축어, 클립보드 기록, 영문·숫자 칸 자동 영문.
- 구조: `Sources/HangulCore/`(맥 의존성 없는 코어, `swift test` 대상) + `App/`(입력기 본체) + `tools/`(진단 도구).
- 빌드: 맥에서는 `./dev.sh` (테스트→빌드→설치→등록), 원격은 아래 참고. `build.sh`가 Core+App 전체를 `swiftc` 한 번으로 한 모듈에 묶어 컴파일한다.

## 원격 빌드 (GitHub Actions, `.github/workflows/release.yml`)

| 트리거 | 동작 |
|---|---|
| 태그 `v*` push | 테스트 → 빌드 → 릴리스 생성 + OGKeyboard.zip 게시 |
| `main` push | 테스트 → 빌드 → 아티팩트 업로드만 (릴리스 없음) |
| 수동 실행 (workflow_dispatch) | 아티팩트 업로드만 |

- 비용: **공개 저장소 + 표준 `macos-15` 러너라 무료** (분량 상한 없음). 저장소를 비공개로 바꾸거나 larger 러너로 바꾸면 macOS 분당 과금이 붙으니 주의.
- 실측: v0.4.0 릴리스 빌드 전체 약 55초.
- 서명: CI에는 인증서가 없어 임시(ad-hoc) 서명 → 업데이트마다 macOS 권한(손쉬운 사용·입력 모니터링)이 풀리는 것이 알려진 제약 (O2에서 개선 예정).

  - 진단(2026-11-14 실기): 로그상 `2자 → 4자`로 지울 개수는 맞음. 스페이스로 먼저 확정한 뒤 바로잡기하면 정상 → 확정(insertText)을 Chromium이 비동기로 처리하는 사이 첫 합성 Backspace가 먼저 도착해 버려지는 것.
  - 1차 수정(확정 뒤 0.08초 지연)은 실기에서 효과 없음 → 시간 문제가 아님.
  - 2차 수정: 키흉내 경로에서는 조합 글자를 확정하지 않고 `setMarkedText("")`로 밑줄째 지운 뒤 기록(TypedText)에만 붙이고, Backspace는 확정된 글자 수만큼만 보냄. 로그에 `(조합 N)` 표시. → 실기: 보낸 Backspace 1개도 버려짐 (Termix는 밑줄이 사라진 직후 첫 키를 버림).
  - 실기 확인: 왼쪽 ⌘로 먼저 확정하고 1~2초 뒤 바로잡기하면 정상 (사이에 키 하나 + 시간).
  - 3차 수정(더미 Shift + 0.15초 대기)도 효과 없음.
  - **진짜 원인 (실기 `stty -icanon -echo; cat -v`)**: 셸이 받은 바이트 = `멱` `ㅓ` `^?` `exit`. Backspace는 버려지지 않았고, **입력기가 밑줄을 지워도(setMarkedText "") Termix(xterm.js)가 조합 글자를 셸에 보냄**. 1차(확정) 방식은 입력기 확정 + xterm.js 전송으로 `ㅓ`가 두 번 들어가 Backspace 2개가 모자랐던 것으로 보임.
  - 4차 수정: 밑줄째 지우는 방식 유지, Chromium 터미널에선 밑줄 글자도 셸에 들어간 것으로 보고 Backspace 개수에 포함. 더미 Shift·대기 제거.
- [x] B14. Termix에서 긴 문장을 연속 바로잡기하면 마지막 글자가 문장 맨 앞에 붙음 (`…지웁니다` → `다지금처럼 확정된 글자만 지웁니`) — **실기 확인 완료 (2026-11-14)**.
  - 원인: `KeySender.type`은 한 이벤트에 UTF-16 16개씩 묶어 보냄. 17자 문장 → 16자 + 1자. Chromium은 1글자 이벤트는 키 경로(xterm.js가 keydown.key로 바로 전송, B12와 같은 경로), 여러 글자 이벤트는 입력 경로로 늦게 처리 → 1자가 먼저 셸에 도착.
  - 수정: 마지막 묶음이 1글자가 되면 앞 묶음에서 한 글자를 넘겨 2글자 이상으로 만듦.
- [ ] B15. 맥 터미널에서 Enter 뒤에도 글자 기록(TypedText)이 남아 다음 줄 바로잡기에 이전 줄 글자가 섞임 (실기 로그: 3번째 낱말 18자 = 이전 줄 8자 + 10자), 첫 줄도 글자가 겹침(`이진이진석이진석`) — **진단 중**. `InputController.handle`에 DIAG 임시 로그 추가 (끝나면 제거).
- [x] B12. Termix에서 일부 기호 키가 원래 글자로 입력됨 (390의 Shift+쉼표·마침표 → `<` `>`) — **원인 재확정·우회 구현·실기 확인 완료 (2026-11-14)**.
  - 원인: Termix는 네이티브가 아니라 **Electron + xterm.js**. 입력기가 조합 글자 없이 1자만 넣으면 Chromium(`render_widget_host_view_cocoa.mm` keyEvent)이 원래 키 정보(key=`<`)로 keydown을 보내고 넣은 글자(`2`)는 keypress로 보낸다. xterm.js `_keyDown`은 한 글자 키를 `ev.key`로 바로 셸에 보내고 keypress를 버린다. 단 key가 A~Z 대문자면 keypress로 미루는 HACK이 있어서 Shift+M(→1)·J(→4)는 정상이었던 것 (11-13 진단의 "Shift 키만 깨짐" 구분은 틀림 — M·J도 Shift 키).
  - 예측(실기로 확인할 것): ① 한글 조합 중(밑줄) 바로 뒤의 Shift+쉼표는 정상 (조합 글자가 있으면 Chromium이 keydown을 229로 보냄) ② 391 자판은 Shift 없는 `-` `[` `]` `\` `` ` `` 등 기호 키 21개도 같은 증상.
  - 우회: 터미널로 다루는 Chromium·Electron 앱(`Terminals` + `ChromiumApps`)에서, 자판이 기호 키를 다른 글자로 바꾸면(`LiteralHold.needsHold`) 그 글자를 바로 넣지 않고 **조합 중 글자로 걸어둔 뒤** 다음 키·확정 때 넣는다 → keydown이 229로 가서 xterm.js가 조합 경로로 받음. 걸어둔 글자는 다음 키까지 밑줄로 보이고, Backspace는 그 글자만 지운다. `commit`·`CommitGuard`는 `hasComposition`으로 걸어둔 글자까지 확정.
  - 효과 없는 대안(기록): 같은 키 처리 안에서 setMarkedText 직후 insertText (끝날 때 marked text가 없어 Chromium 조건 불충족), 폭 0 글자 덧붙이기 (셸에 쓰레기 입력). 차선책: 합성 키 전송(KeySender) — 빠른 타이핑 때 순서 뒤바뀜 위험.
